# HI/H₂ 模型

astrovodka 用四种已发表方案中的一种，为每个 TNG 气体单元指定中性氢
和分子氢的质量。本页说明它们计算什么、彼此有何不同、如何在它们之间
进行选择，以及它们的假设在哪里会出问题。

函数签名、默认值和完整的配置表见 [API 参考](api/himodel.md)；
本页讲的是物理以及由此带来的实际后果。

## 为什么不用 MARTINI 的划分方案

MARTINI 用一个在近邻星系上标定的、基于压强的关系把气体分成 HI 和 H₂。
它不含红移依赖，因此在星系更致密、金属更贫、所处的 UV 场也更强的高红移，
它没有理由是对的。

Diemer+2018 的模型把它换成了由局部条件出发的计算：气体密度、金属丰度，
以及星际辐射场。正因如此，它们才能在 astrovodka 所针对的红移范围内使用。

## 模型计算什么

每个模型都会为每个气体单元给出一个**分子比例**

```
f_mol = M_H2 / (M_HI + M_H2)
```

然后按此拆分该单元的中性气体：

```
M_H2      = f_mol       × M_neutral
M_HI      = (1 - f_mol) × M_neutral
M_neutral = 该单元的中性氢总质量
```

`f_mol` 随气体密度和金属丰度上升 —— 更致密的气体能更有效地把自己
屏蔽在离解辐射之外，而真正起屏蔽作用的是尘埃，因此金属丰度是通过
尘气比进来的。它随 UV 场的强度下降，因为 UV 正是把 H₂ 拆开的东西。

每个单元还会得到一个**中性比例**，它把电离气体也考虑在内；
按构造，`compute_hi_mass` 返回的 `m_neutral` 就等于 `m_hi + m_h2`。

## 2×2：GD14 与 K13，体密度与投影

这四个模型是两套方案族与两种估计方案所需气体面密度的方法的叉积。

| | **体密度** | **投影** |
|---|---|---|
| **Gnedin & Draine 2014** | `GD14_vol` | `GD14_map` |
| **Krumholz+ 2013** | `K13_vol` *（默认）* | `K13_map` |

### GD14 与 K13

两个方案族都从一个辐射场参数和一个以尘气比加权的面密度来预测 `f_mol`，
但它们是在不同的模拟上标定的，对屏蔽的处理也不同。实践中，在 TNG 星系上，
**K13 倾向于比 GD14 产出少得多的 H₂** —— 在子晕 122 上这个比值约为
0.18（`K13_vol`），而 `GD14_vol` 是 0.43。这是两套方案之间真实的物理分歧，
而不是 bug，也正是同时提供两者的主要原因。

### 体密度与投影

- **体密度**模型用每个单元自身的密度和一个 Jeans 长度近似来估计它的
  面密度，`Σ = λ_J · ρ`。完全局部，不需要投影，也不需要恒星粒子。
- **投影**模型构建星系的面向观测者的投影图，并从中读出面密度。
  这更接近观测实际的做法 —— 望远镜测的是一条沿视线的柱，而不是体密度 ——
  也正是 Diemer+2018 在投影变体中采用的做法。

因此投影模型除气体之外还需要**恒星粒子**（用来计算恒星面密度），
开销也更大。它们还必须对落在投影盒之外的气体做出决定 ——
见[需要注意的地方](#需要注意的地方)。

## UV 场

`f_mol` 取决于每个气体单元处的离解辐射场有多强，因此一个模型
再好也好不过它的 UV 场。

**体密度**模型的 UV 场有两个来源，用 `uv_mode` 选择：

| `uv_mode` | 作用 |
|---|---|
| `'adaptive_fft'` *（默认）* | 在三维 FFT 网格上用 1/r² 卷积核卷积星系的恒星形成率分布，给出一个对恒星实际位置有响应的逐单元场 |
| `'global'` | 处处使用均匀的 Faucher-Giguère+2011 河外背景 |

两者都把背景作为**下限**，因此 `'global'` 就是没有恒星形成的星系在
`'adaptive_fft'` 下的极限。在有恒星形成的星系中，两者差别很大：
在教程所用的子晕 113 上，从背景切换到自适应场会让 HI 质量变化约
**+14%**，因为强的局部 UV 场把气体挤出分子相。

**投影**模型的 UV 场由 SFR 图导出，这是方法定义的一部分，因此 `uv_mode`
对它们不适用。把 `'global'` 与一个 `*_map` 模型一起传入会抛出异常，
而不是悄悄忽略这个参数。

> **一个值得了解的 bug。** 在 0.3.0 之前，自适应场并不工作：
> 构建三维插值器时，把某一个轴的坐标复用到了全部三个轴上，
> 于是几乎每个粒子都落在其范围之外，得到 `fill_value=0.0`。
> 结果得到的场在数值上与均匀背景完全相同，也就是说
> `uv_mode='adaptive_fft'` 与 `uv_mode='global'` 给出相同的质量，
> 而分子质量最多错了 42%。守护这一点的测试基于位置，而不是钉死的
> 数值 —— 见[验证记录](verification.md)。

## 如何选择模型

默认值是 `K13_vol`，这是个合理的默认选择：它不需要恒星粒子，
是四者中最便宜的，也是 Diemer+2018 用作基线的那个体密度变体。

| 如果你想…… | 就用 |
|---|---|
| 与 Diemer+2018 星表做对比 | `K13_vol` |
| 匹配观测实际的做法（穿过星系的一条柱） | `K13_map` 或 `GD14_map` |
| 看看换一套方案的效果 | 在 `K13_*` 与 `GD14_*` 之间切换 |
| 用最少的输入数据运行 | 一个 `*_vol` 模型 —— 不需要恒星粒子 |

```python
from astrovodka.sources import TNGSource

source = TNGSource(basePath=..., snapNum=99, subID=113, hi_model="K13_map")
print(source.m_HI_total, source.m_H2_g.sum(), source.f_mol_g.mean())
```

因为这些模型本来就设计成会有分歧，**一定要报告你用的是哪一个**。
没有它，一个标为“HI 质量”的单一数字是不可复现的。

## 调整配置

`HIModelConfig` 是一个冻结（frozen）数据类，保存依赖快照的取值
（`h`、`z`、盒子尺寸）以及各种数值设置。它既可以作为对象传入，
也可以作为普通字典传入：

```python
from astrovodka.himodel import HIModelConfig

TNGSource(..., hi_config=HIModelConfig(h=0.6774, z=0.0, ngrid=64))
TNGSource(..., hi_config={"ngrid": 64})          # 效果相同，会替你合并
```

`h` 和 `z` 始终来自快照，从不来自调用方 —— 刻意如此：把它们显式传给
`TNGSource` 不会有效果，因为快照宇宙学与模型宇宙学之间的不一致
会是无声无息的。

最可能要紧的设置：

| 字段 | 默认值 | 何时修改 |
|---|---|---|
| `ngrid` | 128 | 探索时为了速度可以调低；UV 网格会变粗 |
| `f_esc` | 0.1 | 如果你想测试不同的 UV 逃逸分数 |
| `box_expand` | 1.1 | 自适应 UV 盒超出气体之外多远 |
| `map_clip_outside` | `False` | 见下文 |
| `k13_variant` | `'2p'` | 投影 K13 模型中由哪种方案给出 `n_CNM` |
| `vol_fine_grid` | `0.0` | Diemer+2018 附录 A.2 的第二个、更细的 UV 网格 —— **默认关闭**，见下文 |

## 需要注意的地方

### 落在投影盒之外的气体

投影模型把星系*定义成*它们的投影盒。盒外的单元得到**零** HI 和 H₂ ——
这就是方法本身，而该方法在星表中的总量就是盒内的总量。

落在盒内的气体质量比例会报告为 `f_gas_in_map`，当它低于 0.9 时
`TNGSource` 会给出警告。对教程所用的子晕 113 它是 0.955；
对子晕 122 它是 0.883，低到值得注意。

如果你改为需要质量守恒，可以把盒外的气体夹到边缘像素上：

```python
HIModelConfig(h=0.6774, z=0.0, map_clip_outside=True)
```

这样能守恒质量，代价是把气体堆在边界上，而这未必更好 ——
论文在这里没有指定约定，因此两种做法都说得通，
你应该说明自己用的是哪一种。

### 第二个 UV 网格默认关闭

Diemer+2018 附录 A.2 会把体密度计算跑两遍，第二遍用的网格跨度为
两个气体半质量半径，因为单个粗网格会低估星系中心的 UV 场。
`vol_fine_grid` 实现了这个开关，可测地让 `f_mol` 移动 −3 到 −5 个百分点。

它**默认关闭**有两个原因：论文没有说明如何合并这两个网格；
而且打开它会破坏与参考实现之间的逐位一致性，这一致性记载于
[验证记录](verification.md)。启用它是一种实验，而不是一种修正。

### 内存

体密度模型会构建一个完整的 `ngrid³` 网格，投影模型则是一张
`ngrid_map²` 的图。在默认的 128 下这些都不大，
但气体单元超过约 10⁷ 的子晕会受益于分块，而分块尚未实现。

### 物理层是独立的

`astrovodka.himodel` 不从观测层导入任何东西，因此你可以在来自任何地方的
气体单元数组上使用这些模型 —— 另一个模拟、一条后处理流水线、
一次交互式会话 —— 完全不涉及数据立方体：

```python
from astrovodka.himodel import HIModelConfig, compute_hi_mass

result = compute_hi_mass(gas, model="K13_vol",
                         cfg=HIModelConfig(h=0.6774, z=0.0))
result.m_hi_msun, result.m_h2_msun
```

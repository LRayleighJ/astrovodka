Installation and environment setup

This page covers everything needed to get astrovodka running: supported Python versions, the three supported installation routes, the optional dependencies and what each one unlocks, how to work offline on a cluster, how to lay out your IllustrisTNG data, and how to check that the install is sound.

If you just want the shortest path, it is:

git clone https://github.com/LRayleighJ/astrovodka.git
cd astrovodka
conda env create -f environment.yml
conda activate astrovodka

and then jump to Verifying the installation.

astromartini, numpy, scipy, astropy and tqdm are installed automatically with the package. The rest are opt-in extras, except that you need h5py for any TNG workflow — it is what reads the snapshot files, not just what writes HDF5 output.

Note that astrovodka uses multiprocess, not the standard library multiprocessing. MARTINI parallelises with dill-based serialisation, which the stdlib module does not provide. Installing multiprocess is only necessary if you pass ncpu > 1.

Hardware

The package itself is light, but two features are memory-hungry:

  • Loading a TNG subhalo. Cost scales with the subhalo's particle count. The tutorial's target, TNG-100 snapshot 99 subhalo 113, has 8,169 gas cells and loads in seconds. Cluster cores are a different matter: subhalo 0 of the same snapshot has roughly 38 million gas cells and needs well over 10 GB. Avoid low subhalo IDs, which are the most massive objects (the catalog is sorted by descending mass).
  • The 3D data products and the adaptive FFT UV field build a full ngrid³ grid (128³ by default), which is on the order of 10 MB per grid per array. Subhalos with more than ~10⁷ gas cells would benefit from chunking, which is not implemented.

Disk space for the software itself is negligible (a few MB). Disk space for TNG data is not — see IllustrisTNG data.

Installation

astrovodka is not on PyPI. Install it from a checkout. All three routes below start from:

git clone https://github.com/LRayleighJ/astrovodka.git
cd astrovodka

Route 1: conda (recommended)

environment.yml in the repository root pins the stack that the project is developed and verified against, and installs astrovodka itself in editable mode:

conda env create -f environment.yml
conda activate astrovodka

To use a different environment name, edit the name: line first, or override it on the command line:

conda env create -f environment.yml -n my-env

To update an existing environment after pulling new commits:

conda activate astrovodka
conda env update -f environment.yml --prune

Route 2: virtualenv and pip

Any Python 3.9+ environment works:

python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
python -m pip install --upgrade pip
python -m pip install -e ".[dev]"

[dev] pulls in h5py, matplotlib, multiprocess, pytest and pytest-cov. For a leaner install, name only the extras you need:

python -m pip install -e ".[hdf5]"                 # TNG work, nothing else
python -m pip install -e ".[hdf5,parallel]"        # + multi-core insertion
python -m pip install -e ".[hdf5,parallel,plotting]"   # + figures

If you prefer a plain requirements file over extras:

python -m pip install -r requirements-dev.txt
python -m pip install -e . --no-deps

Editable (-e) is recommended while the code is moving. For a fixed installation use pip install . instead, but note that the examples and tutorials assume the repository is present.

Route 3: core only, no optional dependencies

The physics layer — astrovodka.himodel, which computes per-cell HI and H2 masses from a TNG gas cell array — depends only on numpy, scipy and astropy. It can be used on its own, with no h5py, no matplotlib, and no data cube anywhere in sight:

python -m pip install -e .
from astrovodka.himodel import HIModelConfig, compute_hi_mass

cfg = HIModelConfig(h=0.6774, z=0.0, boxsize_ckpc_per_h=75000.0, ngrid=64)
result = compute_hi_mass(gas, model="K13_vol", cfg=cfg)
print(result.m_hi_msun, result.m_h2_msun)

The package is laid out so that this works: astrovodka.himodel imports nothing from the observation layer (including MARTINI), and import astrovodka does not import h5py or matplotlib. A test enforces both (tests/test_upstream_dependency.py).

h5py is listed as optional because the physics layer genuinely does not need it. In practice, though, every route that touches actual TNG data requires it, so treat it as mandatory unless you are only using astrovodka.himodel.

Offline and air-gapped installs

Cluster login nodes often have no outbound network. Two things need attention.

1. Build isolation. By default pip creates a temporary virtual environment to build the package and downloads setuptools into it. If you already have a recent setuptools, skip that:

python -m pip install -e . --no-build-isolation

pyproject.toml requires setuptools>=64; check yours with python -c "import setuptools; print(setuptools.__version__)".

2. Dependencies. Either pre-download wheels on a networked machine,

# on a networked machine, matching the target Python
pip download astrovodka[hdf5,parallel,plotting] -d wheels/ --no-deps
pip download numpy scipy astropy tqdm h5py matplotlib multiprocess pytest -d wheels/

then copy wheels/ across and install from it:

python -m pip install --no-index --find-links wheels/ -e . --no-build-isolation

or build a conda environment file on a networked machine and transfer it (conda env export > environment.lock.yml, then conda env create -f environment.lock.yml).

3. Conda offline. conda env create --offline works if the packages are already in the local package cache. If your cluster provides TNG data but not a scientific Python stack, conda create -n astrovodka --clone base followed by pip install -e . --no-deps is often the fastest way in, provided numpy, scipy and astropy are already present.

IllustrisTNG data

astrovodka reads TNG data from local disk. It does not use the TNG web API and does not need network access at run time, but it does need the files.

Where to get it

  • TNG-100 / TNG-300 public data release: <https://www.tng-project.org/data/> (registration required). Download the groups_<snap> and snapdir_<snap> directories for the snapshots you want.
  • TNG-50: same site, smaller volumes, good for testing.
  • If you only want the group catalogs (subhalo positions and masses) and not the particle data, groups_<snap> alone is enough to choose subhalos, but not to build cubes.

Expected layout

Point basePath at the simulation directory, i.e. the one that contains groups_<snap> and snapdir_<snap>:

/path/to/TNG/TNG-100/
├── groups_099/
│   ├── fof_subhalo_tab_099.0.hdf5      # group/subhalo catalog
│   └── ...
└── snapdir_099/
    ├── snap_099.0.hdf5                 # particle data, chunked
    └── ...

The snapshot number is zero-padded to three digits. Directory names must match this pattern; TNGSource builds the paths from basePath and snapNum.

Size

For TNG-100, one snapshot's particle data is on the order of 1–2 TB and the group catalog around 13 GB. You do not need every snapshot — for most work one or two is enough. Consider a symlink farm if the data lives on a scratch filesystem with a purge policy.

Telling astrovodka where the data is

There is no global configuration file. Pass the path explicitly:

source = TNGSource(basePath="/path/to/TNG/TNG-100/", snapNum=99, subID=113)

The example scripts and both tutorial notebooks read it from an environment variable instead, so that no path is baked into the repository:

export TNG_BASE_PATH=/path/to/TNG/TNG-100/
python examples/en/astrovodka_demo.py --snapNum 99 --subID 113

Verifying the installation

1. It imports

python -c "import astrovodka; print(astrovodka.__version__)"
python -c "from astrovodka.himodel import METHODS; print(METHODS)"

The second should print ('GD14_vol', 'GD14_map', 'K13_vol', 'K13_map').

2. The optional pieces are there

python -c "import h5py, matplotlib, multiprocess; print('optional deps OK')"

A missing h5py will not stop import astrovodka — by design — but it will fail the moment you load a TNG subhalo.

3. The test suite passes

python -m pytest tests/ -q

The suite is synthetic: it needs no TNG data, no network, and no GPU, and takes about 15 seconds. It covers the four HI models against analytic expectations, the cosmology helpers, the data-cube spectral-axis conversions, the 3D data products, and the self-containment rules described above.

4. The examples run

Without any TNG data:

python examples/en/astrovodka_demo.py

This builds an analytic rotating disc at z = 0.01 and writes a FITS cube to examples/outputs/. It prints a mass-conservation check; the line

Mass in cube (assuming distance ... ): 1.00e+11 solMass
    [100% of initial source mass]

should read 100%.

With TNG data:

export TNG_BASE_PATH=/path/to/TNG/TNG-100/
python examples/en/astrovodka_demo.py --snapNum 99 --subID 113 --hiModel K13_vol

Python version support

Python 3.9 is the floor and the version this release is tested on, together with 3.10 through 3.13 in CI. pyproject.toml declares requires-python = ">=3.9".

Two details are worth knowing:

  • The floor comes from astromartini: releases 2.1.9 through 2.1.15 support Python 3.9, while 2.1.16 and later require 3.10. pip resolves the newest MARTINI available for the interpreter, and astrovodka works with every released version — its rotation adapter detects the 2.1.16 API change at import time.
  • typing_extensions is required on Python 3.9 and 3.10, because MARTINI's datacube uses typing.Self with a typing_extensions fallback but does not declare the dependency itself. astrovodka declares it for those versions.

Because astropy 7 requires Python 3.11 and later, on Python 3.9 pip will resolve an older astropy (6.x), which is supported. The declared floor for astropy is 5.0.

MARTINI's observation machinery is not restyled here, but it is 3.9-clean and CI runs the whole suite on every supported version.

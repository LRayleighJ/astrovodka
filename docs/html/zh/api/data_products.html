数据网格属性

所有网格都是 (ngrid, ngrid, ngrid) 的 float32 数组：

属性 单位 说明
uv_field Draine 单位 UV 辐射场
dm_real M<sub>sun</sub>/(ckpc/h)³ 共动 DM 密度（实空间）
dm_rsd M<sub>sun</sub>/(ckpc/h)³ 共动 DM 密度（红移空间）
hi_real M<sub>sun</sub>/(ckpc/h)³ 共动 HI 密度（实空间）
hi_rsd M<sub>sun</sub>/(ckpc/h)³ 共动 HI 密度（红移空间）
h2_real M<sub>sun</sub>/(ckpc/h)³ 共动 H2 密度（实空间）
h2_rsd M<sub>sun</sub>/(ckpc/h)³ 共动 H2 密度（红移空间）
grid_edges ckpc/h 3 个边界数组组成的元组（长度为 ngrid+1），实空间
grid_edges_rsd ckpc/h 同上，但属于红移空间的盒子，沿视线方向更长
metadata — redshift、hubble_h、网格范围、f_mass_in_rsd_box_* 等

红移空间公式： s<sub>x</sub> = x + v<sub>los</sub> / (a × H(a)) 其中 Δx = v<sub>los</sub> / (a×H(a)) × 1000 × h [ckpc/h]，而 v<sub>los</sub> 是相对于 DM 质心的（与盒子中心同一个参考系，见 metadata['rsd_velocity_frame']）。

两套盒子不同，因此 *_rsd 与 *_real 不能相减。 在 z = 0 时 1 km/s 对应 10 ckpc/h，所以红移空间沿视线方向的尺度由速度范围而非几何决定： 对 subhalo 113 是 2722 ckpc/h，而实空间只有 41 ckpc/h。Δx 是一个*位移*，星系尺度的 盒子装不下它——除非把实空间的网格一起拉伸，那等于让一个红移空间的选择去污染实空间数据。 要比较两者，请比较它们的视线方向剖面，或用 f_mass_in_rsd_box_dm / _hi / _h2 检查有没有丢质量（盒子自适应时恒为 1.000）。

在 1.0.0 之前，位移用的是*绝对*速度且沿用实空间盒子，*_rsd 网格只保留 0.5% 的质量； 任何依赖 dm_rsd − dm_real 的做法，都是拿一张真实的图去减一张几乎空白的图。
